# ADR 0001: v0.1 implementation boundary

Accepted 2026-09-08 by the owner during planning.

The canonical specification is PROJECT_ZERO_SPEC.md, fetched from Google Doc
1LLFTPbh4YMIST0SH27XJmf3ITT1vlHki-crrpNFbu_I (modified 2026-09-08T09:06:26.653Z).
Its document version is distinct from its roadmap stages. This build delivers
v0 and v0.1 with a minimal manual Project Zero session brought forward from v0.2.

- Go modular monolith, SQLite WAL/FULL, one transactional writer; owner-only Unix HTTP API.
- JSON Schema contracts; TLS WebSocket node sessions, per-device asymmetric keys.
- Runtime identity in Apple Keychain; USB bootstrap and owner fingerprint verification.
- CLI pairing and exact-action approvals substitute for the later native cockpit.
- Existing Times Gate classic ESP32 + 128x160 ST7735, BLACKTAB, portrait, 8MHz.
  GPIO18 SCK, 23 MOSI, 5 CS, 16 DC, 17 RESET. Backlight remains on 3.3V.
- Fixed brightness is an explicit exception to section 22.1: do not advertise dimming.
- Onboard BOOT is the proposed input, subject to physical mapping verification.
- Dedicated ESP-IDF Zero firmware replaces AuxDeck after recovery is documented.
- Session toggles are serialized and deduplicated. Offline presses are discarded.
- No Spotify, AI, agents, goals, cockpit, iPhone, OTA, MQTT or general automations.
- No work-device discovery, enrollment or context paths.

The empty project directory is the implementation workspace on build/v0.1;
there is no existing checkout or user code requiring a second worktree.
Implementation remains in this task without subagents, as explicitly selected.

Release gates require automated evidence and separately recorded real hardware
evidence. A successful simulator is not a successful physical milestone.
