# Desk display and link diagnosis — 2026-09-09

User reported recurring online/offline changes during Spotify playback and a persistent horizontal black line through the project header; requested centered artwork with song/artist to its left.

## Findings and changes

- Only one installed production daemon was running. Mac build 4 upgrade had completed.
- A playing-audio serial capture recorded `websocket_client: Could not lock ws-client within 100 timeout`. Audio freshness rejection increased afterward (471 received, 404 accepted). Earlier daemon logs also contained TLS handshake timeouts; those alone do not establish the cause of every outage.
- The pinned Espressif WebSocket component shares a receive/transmit lock by default. Its Kconfig explicitly provides `ESP_WS_CLIENT_SEPARATE_TX_LOCK` to avoid simultaneous send/receive contention. Enabled that setting in both checked-in sdkconfig and defaults; verified generated sdkconfig.h enables it. This addresses an observed send-path failure; sustained hardware verification is recorded below.
- Audio remains coalesced in its own bounded receive queue. Added metadata-only serial diagnostics distinguishing Wi-Fi loss, actual socket disconnect, queue overflow, and accepted audio. No PCM or credentials logged.
- Artwork is now centered at x=48..79, y=85..116. Song and artist start at x=4; bounded two-line song text and one-line artist. The waveform remains on the right. Longer text truncates to fit the 128-pixel screen.
- Pixel tests compile the actual firmware renderer. The centered-artwork assertion fails against the previous renderer and passes against the new renderer. Every project-header glyph row contains lit pixels in the rendered output; no horizontal black stripe is generated by this layout.
- A USB `PANELTEST` command shows a solid white screen for 15 seconds and then restores the current display. User confirmation of that test is pending. A clean software image alone cannot distinguish a physical row fault from controller initialization or transfer behavior. Do not label the panel as dead pixels without that evidence.

- Two native-renderer pixel tests passed; previous layout failed the new positioning assertion.
- Matching Mac build 0.2.0-5 built, signed, installed and health checked. CLI/runtime/app/device now agree; audit chain VALID.

This capture includes the intentional Mac upgrade restart and a subsequent temporary .local DNS lookup failure, so it is not a clean uninterrupted acceptance interval. A fixed-build follow-up is recorded below.
- Runtime under playback: 200 status samples, p95 0.233 ms, RSS 30.625 MiB.

Private local diagnostic logs are under .runtime; no recurring or AI checks were scheduled. Serial-port opening resets this board, so the initial reset is intentional and excluded from subsequent link stability observations.

## Follow-up findings

The unchanged-build follow-up reproduced a disconnect near 64 seconds: TLS read timed out after waveform age had risen to 2,032 ms. There was no TX-lock timeout or queue overflow. The separate-lock change alone therefore did not establish link stability. Connection I/O deadlines were raised from 3 to 10 seconds on both sides, independently of the unchanged 500 ms telemetry deadline; delayed audio is discarded, never replayed. Runtime now logs bounded connection failure metadata to distinguish peer closure from transport timeout.

The user reported a clean white display, making a permanently dead row unlikely. Comparison with Times Gate's Adafruit BLACKTAB initialization found missing frame-rate, inversion, power, VCOM and gamma register programming in Zero's minimal driver. Restored the reference values and sleep-out delay, retaining portrait orientation and 8 MHz SPI. Visual confirmation after that restoration is required before declaring the line resolved.

Build 0.2.0-6 contains these follow-up changes. Go race tests, ESP-IDF/host protocol tests, and renderer pixel tests passed. Final physical results follow.

The user confirmed the black line remains after full BLACKTAB initialization. That change does not resolve the visual defect. A close-up photo is now needed to compare the affected row with the native renderer; no further speculative display-setting changes are planned. Keep this requirement open. The white-screen observation argues against a permanently dark row but does not by itself isolate controller, transfer, or panel behavior.

Mac build 6 upgrade completed with production health check. Final fixed-build capture runs only after that upgrade, with no subsequent restart or flash during its measurement window.
