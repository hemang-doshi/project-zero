# v0.2 independent development preview — 2026-09-09

Status: independent preview implemented; full v0.2 acceptance remains open.
Owner amended sequencing to proceed while Codex observation is unavailable.

## Implemented and verified

- Registered projects with explicit checkout paths, aliases and removal guard;
  session identity, registered-project start, same-project reuse and session end.
- Independent project/activity/attention/media facts, owner assertion/clear,
  provenance/expiry, transactional entity events and projection rebuild. Owner
  context edits use revision checks to reject stale concurrent updates.
- Deterministic reviewable project/focus intents and CLI execution; no model
  calls. Unsupported phrasing requests clarification.
- Bounded read-only Git worker with registered-path enforcement, inherited Git
  environment isolation, no optional index locks or fsmonitor execution, and
  integration revocation. Real Project Zero branch/dirty status observed.
- Typed Git refresh and 45-minute active-focus reminder policies, firing
  history, feedback and UTC daily report. Unreviewed firings are not counted
  as correct. Disable cancellation survives projection rebuild.
- Native SwiftUI menu-bar app, owner Unix-socket transport, native read-only
  Spotify helper, and permission-driven local reminder delivery. Notification
  claims prevent duplicate dispatch; uncertain claimed results are not retried.
- Combined text display firmware and explicit 0.2 render-schema advertisement;
  runtime keeps legacy nodes on the old focus-only payload.
- Metadata-only hook compatibility probe and project-local configuration;
  exact hook definitions still require owner trust. No trust bypass enabled.

## Fresh checks

- `make test`: Go race suite and two Python tests pass with module networking
  disabled. Existing macOS LC_DYSYMTAB race-linker warnings remain.
- `go vet ./...` and `git diff --check`: pass.
- Native Swift suite against the real isolated Unix socket: 3 tests, 0 failures,
  no skips. Covers runtime connection, chunked HTTP and malformed/error replies.
- Host C parser/button tests and ESP-IDF firmware build pass. Firmware is
  0xf0710 bytes, with 36% application partition free. No flash was performed.
- Ad-hoc signed development app bundles build and the ZeroMenu process runs.
- 200 development status calls: p95 0.183 ms; daemon RSS 21.86 MiB. These are
  local status measurements, not end-to-end integration/display latency.

session, Git connection, git-refresh and focus-break enabled. The native app
was opened against that socket. New profiles start disabled. The original

- User visual confirmation of the menu controls remains pending; the native UI
  automation service timed out, so process launch is not claimed as visual QA.
- Spotify permission and actual track observation, native notification consent
  and visible delivery have not been demonstrated. Connect/allow locally.
- Combined display firmware is built but unflashed and unverified on hardware.
  v0.1 soak and physical interruption checks still gate flashing.
- Codex hook delivery is not yet proven in the desktop app. Codex observation,
