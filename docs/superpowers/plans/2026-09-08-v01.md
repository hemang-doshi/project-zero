# Project Zero v0.1 Implementation Plan

Execution: superpowers:executing-plans, in this task, no subagents.
Spec: PROJECT_ZERO_SPEC.md; approved amendments: docs/adr/0001-v01-build.md.

Goal: durable Mac runtime and CLI, simulator, then a paired physical display/button
with manual session control and recovery without duplicate actions.

Architecture: Go modular monolith with SQLite transactional events, projections,
policy, invocations and outbox; owner-only Unix HTTP API; authenticated TLS
WebSocket reference SDK and ESP-IDF desk firmware.

## Delivery gates
- [ ] 1. Repository, canonical specification, ADRs, daemon, migrations, CLI status,
      structured diagnostics, opt-in LaunchAgent; restart persistence verified.
- [ ] 2. Schema-first protocol, simulator and SDK, registration, capability
      advertisement, authorized invocation, correlated result/event/state/audit.
- [ ] 3. Transactional dispatch, dedupe, deadlines, bounded retry, cancellation,
      unknown effects, leases, session fencing, recovery, grants and approvals.
- [ ] 4. Manual session CLI and button loop; elapsed-time recovery and trace.
- [ ] 5. USB resolution, rollback, on-device key generation, pairing, bounded
      firmware, display, BOOT button, watchdog, authenticated reconnect.
- [ ] 6. Physical interruption matrix, 24h soak, latency/memory results, runbooks.

## Task method
For each behavior: write its real boundary test, observe failure, implement,
run focused verification, then commit the independently working slice.
Shared contracts precede consumers. Keep storage, protocol, identity, policy,
runtime orchestration, SDK and presentation separated.

## Acceptance matrix
- Protocol: oversized/malformed/fragmented messages, unknown fields, versions,
  identity mismatch, duplicate IDs, expiry, backpressure.
- Storage: commit/dispatch/result crash points, rebuild without re-execution,
  contention and failed writes; no acknowledgement before durable commit.
- Policy: four permission states, denial precedence, exact payload binding,
  expiry/revocation, revalidation of queued effects.
- Session: duplicated button delivery, debounce, concurrent inputs, pause and
  resume accounting, runtime downtime, no delayed offline toggle.
- Hardware: power and Wi-Fi loss, daemon restart, retained keys, latest display
  within 10 seconds after authenticated reconnect, safe malformed-input handling,
  24h bounded-memory soak.
- Performance: status p95 <100ms; dispatch <250ms excluding device; idle <150MB.
- All core tests runnable offline after dependency installation.

## Constraints
Keep fixed wiring and omit brightness capability. Do not alter Times Gate.
Document recoverable firmware before flash. Never burn irreversible security
eFuses as part of this prototype. Do not mark a hardware gate complete from
simulation or claim a soak without elapsed-time evidence.
