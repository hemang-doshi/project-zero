# Project Zero v0.2 — Useful Personal Loop

Approved by the owner on 2026-09-08. Canonical source: PROJECT_ZERO_SPEC.md.

## Product

Explicit personal project selection and durable focus sessions; read-only Git
and existing Codex-task status; Mac-local Spotify track/artist/playback status;
native SwiftUI menu-bar client; one combined 128×160 desk display. BOOT remains
focus pause/resume. No work-device discovery, repository scanning, coding-job
submission, media controls, artwork downloads, or general automation editor.

## Runtime and interfaces

Retain Go/SQLite authority and owner-authenticated Unix interface. Versioned
migrations preserve existing events, grants, identity, pairing, and history.
Projects have stable identity, name, aliases, and canonical registered paths.
Sessions gain identity, project reference, and end; same-project start returns
the current session, switching requires explicit end-and-start review.
Context dimensions retain provenance, evidence, freshness, and precedence;
clearing an explicit assertion reveals underlying observations.

CLI additions: projects add/list/show/remove; session end; context
show/assert/clear/explain; intent parse/run/explain and run; integrations
list/connect/disconnect/sync; policies list/check/apply/disable; costs today.
All mutations retain dry-run, stable output, authorization and correlation.

## Integrations and presentation

Git: fixed argument arrays, registered paths only, bounded output/timeouts,
15-second active-focus refresh, no fetch, writes, or repository scripts.
Codex: supported interface on the desktop task-owning service; lifecycle and
outcome metadata only, no task resume or undocumented database/UI scraping.
Spotify: native scripting bridge after OS approval, poll every 2 seconds only
while running; never auto-launch. Scoped integration identities submit facts
outside the serialized transaction path. Outages mark observations stale.

Menu bar: project/focus controls, integration and automation status, approvals,
intent review, model usage. Closing UI does not stop runtime. Desk: project,
focus/time, compact Git/agent indicators, Spotify text, connection. Bounded
text/fallback glyphs; negotiated schema with v0.1 fallback. Do not flash before
current soak and required interruption evidence are collected.

## Intent and model boundary

Known focus/project phrases compile locally; ambiguity prompts clarification.
Unfamiliar wording may use the existing Codex account only after a per-request
export preview of text/minimal aliases. Codex owns authentication. Dedicated
parsing session has no repository, shell, filesystem tools, or integrations.
Output is a schema-valid proposal requiring review and normal policy before
execution. One concurrent request, 30-second deadline, 20 requests/day, no
automatic retries. Record provider/model, counts, available tokens, duration
and outcome. Unavailable subscription monetary cost is never fabricated.

## Three automations

1. Refresh Git during active focus and publish material changes silently.
2. Notify once for relevant observed Codex turn completion/failure; no initial
   historical completion notifications.
3. Gentle reminder every 45 accumulated active minutes; paused time excluded,
   session stays running, at most one overdue reminder after downtime.

Durable configuration, firing identity, evidence, authorization and result;
immediate disable cancels queued work. Incorrect-firing feedback and daily
review distinguish reviewed correctness, unreviewed and missed actions.

## Acceptance gates

First close outstanding v0.1 evidence and prove real desktop Codex observation.
If supported observation is unavailable, keep the gate blocked, report exact
incompatibility, and do not substitute simulated status. Development uses
isolated data/simulators and preserves the running physical soak.

Verify migrations/rebuild without effects, restart/session switching, context
precedence, duplicate/stale observations, adapter revocation/outages, actual
Codex completion/reconnect, parser/export restrictions, automation timing and
disable races, UI reconnect, physical bounds/BOOT and backward compatibility.
Core remains offline-capable within existing performance targets.

Implemented, ready for daily evaluation, and accepted are distinct milestones.
Acceptance requires all three routines exercised for 14 days with fewer than
5% incorrect reviewed firings and one-click disable. Unreviewed is not correct.
