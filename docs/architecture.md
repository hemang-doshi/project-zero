# Architecture

Project Zero is a local-first personal runtime with one authoritative daemon (`zerod`). Clients request snapshots and submit typed actions through local interfaces; they do not own committed runtime state.

## Components and trust boundaries

- **Runtime and storage (`core/`)**: Go service, SQLite persistence, policy evaluation, audit/event handling and versioned API. The Unix socket is owner-controlled. Runtime identity is stored in macOS Keychain when built with macOS and CGO; unsupported targets fail closed for production identity.
- **CLI (`cli/`)**: inspection and explicit commands against the local API.
- **Electron cockpit (`apps/desktop/`)**: UI reads runtime snapshots and invokes allow-listed IPC operations. It is a client, not an alternate authority store.
- **Native clients (`apps/macos/`)**: SwiftUI menu and cockpit components use the local runtime and explicitly connected provider bridges.
- **Node firmware (`nodes/`)**: ESP32 desk display and simulator use the versioned node protocol. Pairing and grants are explicit owner actions.

The default node listener is loopback. LAN use must be configured deliberately and uses enrolled client certificates. Keep development state separate from installed runtime state. The project does not claim to defend a machine from an attacker controlling its logged-in owner account.

## Versioning

The generated release manifest contains product/build versions, supported wire protocols, render schemas and database migration version. Product version does not imply wire or migration compatibility. Firmware and native version constants are generated by `tools/release-gen.py`; use its `--check` mode to detect drift.
